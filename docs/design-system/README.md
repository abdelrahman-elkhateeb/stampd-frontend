# Stampd design system · v0.4

Stampd is the design system for the Employee Ops Platform: a multi-tenant HR operations web app for GCC teams (attendance, leave, requests, approvals). It ships in English and Arabic (full RTL), in light and dark, on React + Tailwind v4 + shadcn/ui (Radix).

Visual source of truth: the **Stampd Design System** canvas (boards 01–29). This folder is the implementation source of truth. If the two disagree, this folder wins, and the canvas gets fixed.

## Principles

1. **Zero training.** Each screen has one primary action. Labels use plain verbs, and every screen says what happens next.
2. **Bold where it counts.** Ink outlines and hard shadows appear only on hero moments (check-in card, approval card, first-use empty state). Everything else is quiet.
3. **Never colour alone.** Every status carries an icon and a label, and patterns or shapes where colour can't be told apart.
4. **Two densities, one system.** Comfortable for employees on phones, compact for HR on desktop. Same tokens, switched by `data-density`.
5. **Arabic is first-class.** Logical properties only, its own type scale, native copy, and Intl formatting.

## How to use tokens

```tsx
// apps/web/app/layout.tsx (already wired)
import "@workspace/ui/globals.css"
```

- **Fonts:** `next/font/google` in `apps/web/app/layout.tsx` sets `--font-jakarta`, `--font-plex-arabic` and `--font-plex-mono` on `<html>`. `--font-ui` / `--font-code` in `tokens.css` read those variables, with the `@fontsource` family names as fallback.

- Use **utilities** generated by `@theme inline`: `bg-card`, `text-muted-foreground`, `border-input`, `bg-status-late-bg text-status-late`, `bg-cat-leave`, `shadow-hard`, `h-control`, `rounded-pill`, `text-h2`, `font-black`, `ease-standard`.
- Use **raw variables** only inside component CSS: `var(--ring)`, `var(--elev-hard)`.
- **Theme:** put `.dark` on `<html>`. Because every theme-dependent token is a literal per theme, `.dark` also works on any subtree.
- **Density:** `data-density="compact"` on the HR layout root. Components read `h-control`, `h-row`, `px-cell`, `p-card`, `size-icon`, `text-ui`, `text-cell`.
- **Language:** set `<html lang dir>`. Fonts, the type scale, tracking and case switch automatically through `:lang(ar)`, and `--flip` through `[dir="rtl"]`.
- **Tenant accent:** set `--tenant-accent` inline on `<html>` from company settings. See `layout.md › Tenant branding`.

Every colour pair in `tokens.css` states its contrast ratio in a comment. A new pair must be checked (text 4.5:1, UI boundaries and marks 3:1) in both themes before merge.

## The 10 rules that must never be broken

1. **Never colour alone.** Status = icon + label (+ dashed/pattern where required). Charts = direct labels + line style.
2. **Only tokens.** No hex, px or ms literals in components. If a value is missing, add a token here first.
3. **Butter is a fill, never text** (in-app), and appears at most once per screen section (active nav item, check-in button, one hero stat).
4. **At most one hard-shadow hero per screen.**
5. **Category ≠ status.** Request-type colours (`--cat-*`) follow the pair rule (ΔE ≥ 11 to every status shown beside them). Never use a category colour to mean a state.
6. **Logical properties only** (`ms/me/ps/pe/start/end`, `border-s`, `text-start`). Directional icons get `flip-rtl`. Lint rejects `ml-`/`mr-`, `pl-`/`pr-`, `left-`/`right-`, `border-l/r`, `rounded-l/r/tl/…`, `text-left/right` in `className` and `cn()`/`cva()` (`no-restricted-syntax` in `packages/eslint-config/base.js`; lint runs with `--max-warnings 0`).
7. **Company time, always.** Timestamps are shown in `company.timezone`. Calendar days are plain dates formatted with `timeZone: 'UTC'`. Never use device time.
8. **Everything is keyboard-reachable with a visible focus ring.** Touch targets are at least 44×44.
9. **Contrast holds in both themes:** text 4.5:1, UI 3:1, verified, not assumed.
10. **Never reveal more than the viewer may see.** Colleagues appear as "Out", with no leave type or reason. Destructive actions confirm, and rejections need a reason.
